# Как этим пользоваться

Набор кладётся в корень пустого репозитория до первой строчки кода.

```
CLAUDE.md                     ← подхватывается автоматически каждую сессию
docs/01-product-brief.md      ← кто пользователь и что в scope
docs/02-architecture.md       ← стек, маршруты, кеш, безопасность
docs/03-data-model.md         ← prisma-схема и правила работы с ней
docs/04-design-system.md      ← токены, типографика, что запрещено
docs/05-video-pipeline.md     ← телеграм → bunny → HLS
docs/06-roadmap.md            ← задачи с критериями приёмки, рабочий файл
docs/07-testing.md            ← что тестируем и чего не тестируем
.claude/rules/*.md            ← правила, подгружаются по маске файлов
.claude/skills/ui-review/     ← /ui-review, проверка экрана перед сдачей
.claude/skills/add-episode/   ← /add-episode, прогон конвейера видео
.claude/agents/reviewer.md    ← ревью дифа в отдельном контексте
.claude/settings.json         ← форматирование и typecheck по хукам
```

## Порядок работы

1. `git init`, скопировать файлы, закоммитить.
2. Открыть Claude Code в папке. Проверить `/memory` — должны загрузиться
   CLAUDE.md и правила из `.claude/rules/`.
3. Первая задача из `docs/06-roadmap.md`, фаза 0. Формулировка простая:
   «возьми следующую невыполненную задачу из роадмапа, покажи план».
4. После каждой задачи, где менялся интерфейс: `/ui-review`.
5. Перед коммитом: субагент `reviewer` по дифу.

## Что править по ходу

Роадмап — живой файл, отмечай сделанное там же. Дизайн-док и модель данных —
источник правды: если реальность разошлась с ними, чинится док, а не память.

Файл `docs/05-video-pipeline.md` ждёт результатов `ffprobe` — впиши их, это
первое, что определит стоимость проекта.

## Заполнить до старта

- Актуальные тарифы Bunny и расчёт на 1 000 / 5 000 / 20 000 просмотров
- Домен
- Логотип и фирменные цвета студии, если они есть (иначе работает палитра из
  дизайн-дока)
