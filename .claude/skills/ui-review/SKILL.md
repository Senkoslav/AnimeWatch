# UI review

Проверка экрана перед сдачей. Не косметика — поиск того, что придётся
переделывать после показа заказчику.

## Что сделать

1. Подними дев-сервер, если он не запущен.
2. Playwright-скриптом сними экран на 360×800 и 1440×900, в обоих случаях
   полностраничный скриншот. Сохрани в `.tmp/ui-review/`.
3. Посмотри скриншоты. Не описывай их пересказом — ищи расхождения.
4. Прогони `@axe-core/playwright` по этой странице.
5. Проверь клавиатуру: пройди по табу до конца, зафиксируй, где пропал фокус.

## По чему сверять

Дизайн-система (`docs/04-design-system.md`):

- цвета только из токенов, янтарный акцент — только на активном состоянии
- радиусы из набора 4 / 8 / 999, теней нет
- шрифты Unbounded для дисплея и Golos Text для текста, размеры из шкалы
- нет ALL CAPS-лейблов, нет выделения одного слова цветом, нет `→` в кнопках
- нет анимаций появления секций при скролле

Вёрстка:

- на 360px нет горизонтального скролла и обрезанного текста
- тач-цели не меньше 44×44
- длинные названия аниме не ломают карточку — проверь самым длинным в базе
- пустое состояние и состояние загрузки выглядят осмысленно
- изображения не вызывают сдвига макета

Текст:

- кнопка называет действие, названия согласованы между экраном и результатом
- ошибки говорят, что произошло и что делать
- нет маркетинговой воды и текста ради заполнения

## Формат вывода

Список замечаний, каждое одной строкой: `[блокер|важно|мелочь] файл:строка — что не так`.
Блокер — ломает использование или нарушает порог качества из дизайн-дока.
В конце — одно предложение о том, что на экране лишнее и что стоит убрать.

Не правь код в рамках этого скилла. Сначала список, потом отдельная задача.
