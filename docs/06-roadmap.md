# 06. Роадмап

Рабочий файл. Claude Code: отмечай `[x]` только после прохождения критериев
приёмки и `pnpm verify`. Задачи внутри фазы идут сверху вниз — порядок не
случайный.

Обозначения: `S` ≈ полдня, `M` ≈ день, `L` ≈ два-три дня.

Цель всего списка — отправить заявку в Kodik с ссылкой на работающий сайт
(`docs/05-kodik.md`). Всё, что этого не приближает, ждёт.

## Готово до смены направления

Проект начинался как сайт фандаб-студии BebraDub и 2026-09-18 сменил
направление на каталог аниме AnimeWatch. Переживает смену и уже сделано:

- [x] `M` Каркас: Next.js App Router + TS strict, Tailwind с токенами из
      дизайн-дока, ESLint + Prettier, Vitest, Playwright, pnpm-скрипты.
- [x] `S` Prisma: схема, миграции, идемпотентный seed.
- [x] `M` Главная: герой с последним выпуском, лента свежих серий.
- [x] `M` Каталог: фильтры по жанру, году, статусу, типу; состояние в URL.
- [x] `M` Страница тайтла: описание, список серий, ISR, 404 для черновика.
- [x] `M` Поиск на `pg_trgm`, устойчивый к опечаткам: «наруот» находит «Наруто».

Откатано вместе со студией: воркер MTProto, Bunny Stream, свой плеер на
Video.js, раздел «Команда», новости. Код остался в истории git.

## Фаза A. Переименование и вычистка

- [x] `M` AnimeWatch вместо BebraDub: доки, тексты интерфейса, env, схема.
      Удалить воркер, Bunny, свой плеер и всё, что их обслуживало; добавить
      `SourceType.KODIK` и слот плеера с фреймом.
      **Приёмка:** `pnpm verify` и `pnpm build` зелёные, e2e проходят,
      в коде и доках нет упоминаний BebraDub, Bunny и своего плеера;
      страница просмотра показывает фрейм или состояние «источник не подключён».

## Фаза B. Импорт каталога

- [x] `M` Клиент Shikimori: GraphQL, User-Agent, троттлинг 5 rps / 90 rpm,
      повторы, zod на ответ. Маппинг в `Title`.
      **Приёмка:** юнит-тесты маппинга на замоканной сети; троттлинг виден в
      логе при пакетном импорте.
- [x] `M` CLI `pnpm import:shikimori`: по id, по ссылке и пакетом «топ N».
      Серии создаются из числа вышедших; у фильмов одна серия.
      **Приёмка:** повторный запуск идемпотентен по `shikimoriId`; в локальной
      базе 100 тайтлов с постерами; каталог и поиск работают на них.
- [x] `S` Каталог в две колонки: фильтры в своей панели справа, выдача в своей.
      На телефоне фильтры свёрнуты в «Фильтры» над выдачей.
      **Приёмка:** на 1440 панель фильтров справа от сетки и липнет при
      прокрутке; на 360 нет горизонтального скролла и первый ряд постеров виден
      без раскрытия фильтров; e2e каталога и axe зелёные.
- [x] `S` Оценка и популярность с Shikimori: `Title.score` и
      `Title.popularityRank`, бейдж оценки на карточке, сортировки «по
      рейтингу» и «по популярности». Числового поля популярности у них нет —
      только сортировка, поэтому ранг берётся позицией в ответе (`docs/03`).
      **Приёмка:** прогон `--top` по живому API даёт узнаваемый топ (Атака
      титанов, Тетрадь смерти, Стальной алхимик) местами 1..N без пропусков и
      дублей; «по рейтингу» даёт другой порядок; бейдж не ломает карточку с
      длинным названием на 360.
- [ ] `S` Поиск по названию внутри каталога: поле в панели фильтров, запрос в
      `?q=`, тот же `pg_trgm`, что и на `/search`. Складывается с фильтрами.
      **Приёмка:** `?q=` вместе с жанром и годом сужает выдачу; канонический
      адрес не зацикливается на запросе из двух слов.
- [ ] `M` Поиск в модалке по клику на лупу: `<dialog>` поверх страницы с живой
      выдачей, `/search` остаётся отдельной страницей для прямых ссылок и
      поисковиков. Первый клиентский островок в проекте — только он, не шапка.
      **Приёмка:** модалка открывается и закрывается с клавиатуры, фокус
      возвращается на лупу; без JS лупа по-прежнему ведёт на `/search`.
- [ ] `M` Плотная главная: лента новых серий вместо героя во весь экран, ниже
      колонки по статусу и сетка недавно добавленных. Ориентир по плотности —
      animelib, оформление своё (`docs/04`).
      **Приёмка:** на 1440 первый экран показывает ленту и начало колонок, а не
      один постер; на 360 нет горизонтального скролла; axe чист; `/ui-review`
      без критичных замечаний.

## Фаза E. После доступа

- [ ] `M` Сопоставление нашего каталога с их базой, заполнение `Source`.
      **Приёмка:** у тайтлов с озвучкой в Kodik серии играют.
- [ ] `S` Rate limit на поиск и `/anime/*`: перебор случайных slug плодит

- [ ] `M` Вход через Google: OAuth 2.0 code flow своими руками, сессия
      случайным токеном в `Session` и httpOnly-куке. `User.tgId` уходит,
      вместо него `googleId` и `email`. Секрет и обмен кода — только на
      сервере.
      **Приёмка:** вход и выход работают, кука `HttpOnly; Secure; SameSite=Lax`,
      чужая сессия не подделывается подменой id в куке; в клиентский бандл не
      утёк ни один секрет.
- [ ] `M` Отметки и оценки: `Bookmark.state` (смотрю, брошено, просмотрено,

      странице тайтла и в карточке каталога, всё через server actions с
      проверкой сессии первой строкой.
      **Приёмка:** отметка и оценка переживают смену устройства; аноним видит
      приглашение войти, а не молчащую кнопку.
- [ ] `S` Страница профиля: сколько просмотрено, брошено и запланировано,

      **Приёмка:** счётчики сходятся с содержимым `Bookmark`; пустой профиль

- [ ] `M` Каталог манги: метаданные с Shikimori, свои отметки и оценки.

- [ ] `S` Аналитика и Sentry.
- [ ] `M` Прогон чек-листа качества из дизайн-дока по всем экранам на 360px.

## Открытые вопросы

Решаются в задаче, указанной в скобках; решение записывается в соответствующий
док, пункт отсюда удаляется.

- **Формат API Kodik** (Ф C). Точный запрос, имя параметра под `shikimoriId`,
  вид ссылки на плеер и нужен ли токен в самой ссылке — неизвестны до выдачи
  доступа. Интеграция поэтому закрыта одной функцией в `lib/kodik/`.
- **Контакты и домен** (Ф D). В заявке нужен домен; свой выглядит серьёзнее
  `vercel.app`. Контактный адрес нужен на `/dmca` и в юридических текстах —
  сейчас там стоит TODO.
- **Юридические тексты** (Ф D). `/terms` и `/privacy` написаны по фактическому
  поведению сайта и не проверены юристом; в них помечено, что нужно от
  владельца.
- **Пагинация серий** (Ф E). Предел на показ уже стоит: `episodeWindow()`
  выдаёт 100 серий — последние или окно вокруг просматриваемой, — и страница
  пишет, какой диапазон показывает. Остаётся сам переход по диапазонам: у
  «Ван-Пис» 1178 серий, и середина списка сейчас недостижима ссылкой.
- **Манга в модели данных** (Ф E). Либо `Title` получает тип носителя и
  остаётся один каталог, либо у манги своя модель. `Episode` и `Source` для
  манги пустые, а тома и главы аниме не нужны: оба варианта что-то ломают.
- **18+ в каталоге манги** (Ф E). Shikimori отдаёт и хентай. Пускать его на
  сайт — это возрастной барьер и почти верный отказ по заявке в Kodik, поэтому
  по умолчанию импорт такие тайтлы отбрасывает; нужно решение владельца.
- **База для превью Vercel** (Ф D). Главная — ISR и рендерится на `next build`,
  так что сборка без `DATABASE_URL` падает. Превью нужна своя база (ветка Neon)
  с данными.
- **Cache Components** (Ф D). Каталог динамический и ходит в базу на каждый
  показ: без `cacheComponents` кешировать данные можно только устаревающим
  `unstable_cache`. Включение флага меняет модель кеша всего приложения —
  отдельная задача с замером нагрузки.
- **Замер LCP** (Ф D). Lighthouse в режиме `simulate` на `localhost` даёт LCP
  3.3 с независимо от вёрстки; `devtools`-троттлинг даёт 1.6 с. Приёмку по LCP
  мерить на превью Vercel.
- **Поиск на объёме** (Ф E). Счёт считается выражением, поэтому GIN-индексы
  `gin_trgm_ops` планом не используются и каждый запрос — полный скан `Title`.
  На сотнях тайтлов это доли миллисекунды; на десятках тысяч отбор кандидатов
  переводится на оператор с порогом.
- **Отложенная публикация** (Ф E). `publicEpisodeWhere()` пропускает
  `publishedAt` в будущем: серия с датой «на завтра» видна сразу.

## Осознанно отложено

Комментарии, рецензии, рекомендации, донаты, мобильное приложение, свой плеер,
своё хранение видео, мультиязычность. Не начинай эти задачи без явного решения.

Отдельно: читалка манги. Страницы манги пришлось бы либо хранить у себя, либо
тянуть с пиратского агрегатора — и то и другое ломает единственную защиту
проекта, что чужого контента мы не держим. Каталог манги по метаданным в
роадмапе есть, читалки не будет.
