# 02. Архитектура

## Топология

```
  Shikimori API  ──►  CLI импорта  ──►  PostgreSQL
                                            │
                                            ▼
     Браузер зрителя  ◄────────────  Next.js (Vercel)
            │
            │ фрейм плеера
            ▼
     Kodik (их плеер, их CDN)
```

Видеотрафик нас не касается: браузер зрителя общается с поставщиком напрямую
внутри фрейма. Next.js отдаёт HTML со ссылкой на фрейм, и всё.

## Компоненты

**Web (Vercel).** Next.js App Router, SSR/ISR для публичных страниц. Vercel
запрещает раздачу видео через свою сеть — нам это и не нужно, но любой код,
который начнёт проксировать видеопоток, ошибка проектирования.

**База (Neon, Postgres).** Prisma. Connection pooling обязателен:
serverless-функции открывают соединения агрессивно.

**Импорт (CLI, локально).** Скрипт тянет метаданные из Shikimori и пишет в
базу. Не сервис, не воркер, не очередь: наполнение каталога — редкая
операция, которую запускает человек.

**Kodik.** Их база озвучек, их плеер во фрейме, их CDN. Доступ к базе — по
токену, который выдаёт их поддержка (`docs/05-kodik.md`).

## Маршруты

```
/                         главная: свежие серии
/catalog                  каталог с фильтрами (searchParams = состояние)
/anime/[slug]             страница тайтла
/anime/[slug]/[episode]   просмотр: фрейм плеера
/search                   поиск
/dmca, /terms, /privacy   обязательные страницы
/login                    вход: страница для прямого захода и работы без JS
```

Вход открывается модалкой через параллельный слот `app/@auth` и перехват
`(.)login`: клиентский переход на `/login` рисует окно поверх текущей страницы,
прямой заход и перезагрузка — обычную страницу с той же карточкой. Пустой
`@auth/default.tsx` закрывает слот при заходе на любой другой адрес. Catch-all в
слоте, как в документации Next, не ставим: он попадает в `typedRoutes` как
`/[...catchAll]` и разрешает ссылку на любой несуществующий адрес. Вместо него
окно само не рисуется, когда адрес ушёл с `/login` (`components/auth/auth-dialog.tsx`). Ссылки, которым перехват не нужен (сама `/login` из модалки,
`/api/auth/google`), — обычные `<a>`, а не `Link`.

Роутов `app/api/*` сейчас нет: снаружи нас никто не вызывает. Появятся, когда
появится то, что действительно вызывается извне.

## Кеширование

- Страница тайтла — ISR, `revalidate: 300`. Точечный сброс (`revalidatePath`)
  понадобится, когда появится админка; пока правки идут импортом и деплоем.
- Каталог — динамический рендер: фильтры в `searchParams`, а их чтение
  отключает статику. Нечистые адреса (пустые поля формы, мусор) редиректятся
  на канонический URL из `lib/catalog/params.ts`.
- Поиск — динамический по той же причине. Канонический адрес собирается
  `lib/canonical.ts`; кодирование там, в `searchHref` и в `catalogHref` должно
  совпадать, иначе редирект на канонический адрес зациклится на запросе из двух
  слов. В `catalogHref` к этому добавляется порядок: параметры идут в том же
  порядке, что поля формы, и `q` первый в обоих местах. Жанр и тип повторяемые
  (`?genre=A&genre=B`), поэтому порядок нужен и внутри параметра: жанры выводятся
  по алфавиту, типы — в порядке `KIND_OPTIONS`, и ровно в этом же порядке их
  отправляет панель отбора. Год диапазоном — две независимые границы
  `year_from`/`year_to`; заданные наоборот они меняются местами, а не дают пустую
  выдачу. Сортировка из формы вынесена в ссылки над выдачей и переживает отправку
  скрытым полем: иначе она требовала бы второй кнопки «Применить».
- Главная — `revalidate: 60`.
- Страница просмотра — динамическая (`force-dynamic`): скрытие тайтла по
  жалобе должно действовать сразу.
- `/terms`, `/privacy` — `revalidate: 86400`. `/dmca` — `force-dynamic`:
  в ответе состояние отправки формы.

## Безопасность

- Адрес фрейма приходит из базы и проверяется по списку доменов поставщика
  (`lib/watch/embed.ts`). Без проверки строка в базе превращается в чужой
  фрейм на нашей странице.
- У фрейма нет `sandbox` (он ломает плеер поставщика), поэтому список доменов
  — единственная защита. Относиться к нему соответственно.
- Публичная форма `/dmca`: zod на входе, поле-ловушка, лимит 5 обращений в час
  на хеш IP. Соль хеша обязательна в проде: без неё sha256 от IPv4
  перебирается за секунды.
- Роли: `USER | ADMIN`. Проверка роли в каждом server action первым делом, не
  в UI. Исключение — форма обращения: её присылает посторонний.
- Rate limit на поиск и `/anime/*` — в роадмапе перед запуском: перебор
  случайных slug плодит ISR-записи с 404.
- Токен Kodik и соль DMCA живут только в серверном коде.

## Env

```
DATABASE_URL             # через пулер: рантайм и next build (ISR-страницы рендерятся на сборке)
DIRECT_URL               # напрямую: миграции и prisma studio
SHADOW_DATABASE_URL      # пустая база для «примерки» миграций, только локально
KODIK_API_TOKEN          # база и ссылки на плееры; без него страница просмотра честно пустует
TELEGRAM_BOT_TOKEN       # уведомление об обращении правообладателя
DMCA_TG_CHAT             # чат, куда уходит уведомление
DMCA_IP_SALT             # соль для хеша IP заявителя
NEXT_PUBLIC_SITE_URL
```

## Решения и их причины

| Решение | Почему так, а не иначе |
|---|---|
| Фрейм поставщика, не свой плеер | у поставщика свой плеер, свои дорожки и своя раздача; свой плеер тянул 384 КБ JS и не давал ничего |
| Kodik, не своё хранение | хранение и транскод чужого видео — это и деньги, и прямая правовая ответственность |
| Метаданные из Shikimori, не из Kodik | публичный API без токена: каталог наполняется до того, как выдан доступ |
| Импорт из CLI, не админка | наполнение редкое, а админка — это ещё и авторизация, и роли, и UI |
| Postgres, не MongoDB | связи тайтл↔серия↔источник реляционные по природе |
| Аккаунты отложены | ни Kodik, ни первая версия сайта их не требуют; прогресс анонима живёт во вкладке |
