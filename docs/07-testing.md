# 07. Тестирование

Тесты здесь не ради покрытия. Они закрывают места, где поломка тихая и дорогая:
подписи, приватность черновиков, деньги за трафик, конвейер видео.

## Уровни

**Vitest** — чистая логика: маппинг Shikimori → `Title`, разбор подписи Telegram,
генерация подписанных URL, парсер `inventory.csv`, утилиты форматирования.
Сеть и БД замоканы, тест идёт миллисекунды.

**Vitest + тестовая БД** — запросы Prisma и server actions. `pnpm test:db`,
Vitest-проект `db`: отдельная база `bebradub_test` (локальный Postgres или
service-контейнер в CI, URL в `TEST_DATABASE_URL`, имя обязано кончаться на
`_test`), `prisma migrate deploy` перед прогоном, `TRUNCATE` всех таблиц перед
каждым тестом, файлы по очереди. Не транзакция с откатом: код под тестом сам
открывает транзакции Prisma. Хелперы публичной выдачи проверяются на базе
напрямую, а не только через запросы поверх них: запрос может сам по себе
спрятать сломанный фильтр.

**Playwright** — пользовательские сценарии целиком. Проекты: `chromium-desktop`
и `mobile-chrome` (Pixel 7). Мобильный прогон обязателен, это основной трафик.
Плеерный спек (`tests/e2e/player.spec.ts`) идёт в Google Chrome
(`channel: "chrome"`): Chromium из Playwright не декодирует H.264. В CI нужен
`pnpm exec playwright install chrome`. Bunny в e2e заменён фикстурой HLS и
ненастоящими ключами из `playwright.config.ts` — живой CDN тесты не трогают.

## Что тестируем обязательно

Приватность и доступ:
- черновик (`publishedAt = null`) не виден анониму нигде: ни на странице тайтла,
  ни в каталоге, ни в поиске, ни в sitemap
- `Title.status = HIDDEN` убирает тайтл и все его серии из публичной выдачи
- `/admin` закрыт для `USER`, каждый server action проверяет роль
- подделанная подпись Telegram отклоняется
- вебхук Bunny с неверной подписью возвращает 401

Деньги и видео:
- `/api/playback` не отдаёт URL для неопубликованной серии
- подписанный URL протухает, а свежий работает
- срок жизни токена больше длительности серии

Плеер (e2e):
- открыл серию → нажал play → пошло время
- перемотка меняет позицию
- «следующая серия» ведёт на правильный номер
- позиция восстанавливается при повторном открытии
- всё то же самое доступно с клавиатуры

Конвейер:
- `FLOOD_WAIT` переводит задачу в ожидание, а не в `FAILED`
- повторный вебхук по той же серии не плодит дубли `Source`
- перезапуск упавшей задачи из админки работает

## Доступность

`@axe-core/playwright` прогоняется на главной, каталоге, странице тайтла и
странице просмотра. Нарушения уровня `critical` и `serious` роняют сборку.
Отдельно проверяется, что фокус виден и что по табу можно пройти плеер целиком.

## Производительность

Lighthouse CI на главной, каталоге и странице тайтла, мобильный профиль.
Бюджеты: LCP < 2.5 с, CLS < 0.1, TBT < 200 мс, вес JS на первой загрузке
< 200 КБ gzip. Превышение — падение пайплайна, а не предупреждение в логе.

## Чего не тестируем

Вёрстку попиксельно. Скриншотные тесты на верстающемся проекте дают ложные
падения каждый день и обучают игнорировать красный CI. Визуальное качество
проверяется скиллом `/ui-review` вручную перед сдачей фазы.

Не пишем тесты на геттеры, на то, что Prisma работает, и на верстку статичных
страниц.

## Данные для тестов

Фабрики в `tests/factories`, не общий seed-дамп (e2e пока идут на dev-базе
после `pnpm db:seed`). Каждый тест создаёт ровно то,
что ему нужно. Фикстуры внешних ответов (Shikimori, вебхук Bunny, Telegram
Login) лежат в `tests/fixtures` и обновляются вручную при изменении контрактов.

## CI

На каждый PR: `typecheck → lint → test:unit → build → test:e2e → lighthouse`.
Ветка не мержится с красным пайплайном. Флаки-тест либо чинится в тот же день,
либо удаляется — «иногда падает» хуже, чем «нет теста».
